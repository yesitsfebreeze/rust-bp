# Activity and compiler events

Documentation index: [llms.txt](../llms.txt).

just viz shows the project's own tool calls and builds: time, duration, outcome,
inputs and audit alerts. j/k or arrows move, g/G go newest/oldest, q quits.
The clock advances even without new events. Historical failure counts remain
after recovery. Use cargo run --release -p daemon --bin viz -- --once for a
snapshot or --heatmap for the timeline. Unrecorded activity is not proof of success.

The runtime records to events.jsonl. cargo run -q -p daemon -- dir prints its
directory; DAEMON_DIR overrides it for isolated tests. Only the runtime's own
usage is tracked. No agent-specific notification or usage adapters are needed.

MCP streams compile_failed events as standard notifications/message records.
The client's notification handling determines how these are displayed.
Use events {"errors_only":true} to inspect stored failures at any time.
kind:all includes tool activity; next_cursor supports paging.

The supervisor records one event per build. Optional per-crate compiler events:

    cargo install --path src/runtime/daemon --bin rustc-events

Configure RUSTC_WRAPPER=rustc-events or a local .cargo/config.toml with
[build] rustc-wrapper = "rustc-events". Keep it stable: Cargo fingerprints
include the wrapper, so toggling it triggers rebuilds. Compiler output and exit
status are preserved; the supervisor avoids duplicate events.

Commands own process trees and clean up on completion, timeout and cancellation.
Docker jobs have unique names and remove their containers. Cleanup failures are
reported; abrupt process termination cannot execute an in-process cleanup handler.
For startup problems, check the registered runtime path, cwd and stderr, following
[install.txt](install.txt). See [testing](testing.txt) for isolated failure tests.
