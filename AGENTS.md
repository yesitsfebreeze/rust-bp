# Workspace guidance

For repository work, read `docs/workflow.txt` and follow its workflow.
Use `llms.txt` to find task-specific documentation.
Answer ordinary conversation and subjective opinions directly from available
context; mentioning Codex or tooling does not require a skill or file lookup.
Ground evaluations in evidence: distinguish capabilities visible in tool descriptions
from behavior actually observed. A long tool list alone does not demonstrate overhead,
conflicts, or poor reliability. Do not invent drawbacks to balance an opinion, claim
experience you have not had, or prescribe removing tools without a concrete reason.
Give specific, useful judgments and state uncertainty briefly when evidence is limited.
When the user asks to resolve a problem, assess the evidence, list concrete fixes,
implement them, and verify the result. Follow-up questions do not cancel that work.
